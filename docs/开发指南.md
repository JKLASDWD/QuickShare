# 开发指南

[首页](../README.md) · [部署](服务端部署指南.md)

## 1. 准备环境

Windows 安装 Git、Node.js 24、CMake 和 Visual Studio C++ 构建工具，包含 Windows SDK 22621 或更新版本。

| 目录 | 内容 |
| --- | --- |
| client/ | 客户端、界面和应用声音原生源码 |
| server/token-service/ | 鉴权、房间管理与连接凭证 |
| deploy/ | 部署脚本与服务器模板 |
| docs/ | 使用、部署与构建文档 |
| scripts/ | 源码发布打包 |

## 2. 从源码运行

```powershell
cd client
npm ci
npm run build:native
npm start
```

`npm ci` 使用仓库中的图标并准备浏览器依赖，不会覆盖现有图标；原生音频模块需要单独构建。Linux 仅部署服务端。

## 3. 构建客户端

```powershell
npm run dist
```

便携版和安装版输出到 `client/dist/`，打包时校验音频模块及备用副本。分发客户端需保留构建产物中的第三方许可材料。

版本统一维护在 `client/package.json` 和 `client/package-lock.json`。

## 4. 打包源码

在 Windows 的 Git 工作副本根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-source.ps1
```

源码 ZIP 输出到 `release/`，仅包含公开源码与文档，排除配置、证书、依赖、编译结果及本地开发归档；不会覆盖已有压缩包。

发布前执行 `git diff --check`，核对配置示例没有真实凭证。测试工具和历史开发资料由维护者在仓库外存档。

## 5. GitHub 自动构建与发布

- 推送 `main`：检查源码并在 Windows 构建便携版和安装版，可在 Actions 的 Artifacts 下载，保留 30 天。
- 推送 `v版本号` 标签：自动构建并发布到 Releases，附带源码 ZIP、第三方许可和 SHA-256 校验值。
- 手动构建：Actions → Build and release Windows client → Run workflow。

发布新版本时先更新 `client/package.json`、锁文件中两处版本号及 README，再提交并推送。标签必须与版本一致，例如：

```bash
git push origin main
git tag v1.0.0
git push origin v1.0.0
```

每个版本使用新标签；已有 Release 的文件不会自动覆盖。工作流使用 GitHub 自带的令牌，无需手动填写发布 Token。`client/assets/icon.png` 必须保留在源码中，可替换为新的 256×256 或更大 PNG 图标。
