# 服务端部署

[首页](../README.md) · [Cloudflare](Cloudflare部署指南.md) · [无域名 HTTPS](IP自签名HTTPS部署.md)

## 1. 准备服务器

使用有公网 IPv4 的 Linux 服务器，安装 Bash、OpenSSL、curl、sed、awk，下载源码。`deploy/` 与 `server/` 保持原有相对位置。

域名部署先将 A 记录指向服务器，Cloudflare 首次部署保持灰云。已有宿主机 Nginx 需提前准备有效域名证书。

## 2. 放行端口

同时检查云安全组和服务器防火墙，保留 SSH 管理端口。

| 部署方式 | 入口端口 |
| --- | --- |
| 域名 HTTPS / 已有 Nginx | TCP 80、443 |
| IP 自签名 HTTPS | TCP 8989，或实际选择的 HTTPS 端口 |
| 可信内网 HTTP | TCP 8080、7880，仅允许内网/VPN |

所有模式还需 **TCP 7881、UDP 3478、UDP 50000–60000**，用于画面和声音。公网不要开放内部 API/信令端口 8080、7880。

## 3. 运行部署脚本

在源码根目录执行：

```bash
bash deploy/install.sh
```

按提示选择：

| 选项 | 适用环境 | Compose 文件 |
| --- | --- | --- |
| 1 | 域名 HTTPS，Caddy 自动证书 | docker-compose.yml |
| 2 | 无域名，IP 自签名证书 | docker-compose.selfsigned.yml |
| 3 | <a id="lan"></a>可信内网或 VPN，HTTP | docker-compose.ip.yml |
| 4 | 已有宿主机 Nginx 与证书 | docker-compose.nginx.yml |

输入域名或 IP、项目名等，确认摘要后启动。首次运行生成独立密钥和访问令牌；再次运行沿用已有配置、部署方式和项目名。未安装 Docker 时可选择安装；已有 Docker 需运行正常且包含 Compose 插件。

<a id="nginx"></a>
已有 Nginx 方案会询问证书和站点路径，生成配置并执行 `nginx -t`；已有站点替换前会询问并备份。需申请证书时可先按 [Certbot 官方指引](https://certbot.eff.org/)完成。

只生成配置，不启动服务：

```bash
bash deploy/install.sh --configure-only
```

<a id="configuration"></a>
## 4. 连接客户端

脚本检查健康接口及带令牌的房间接口，成功后打印客户端地址。访问令牌是 `deploy/.env` 中的 `AUTH_TOKEN`；仅提供给获准用户。

配置的职责：

| 文件 / 字段 | 用途 |
| --- | --- |
| deploy/.env | 地址、端口、服务端密钥与客户端访问令牌 |
| deploy/livekit.local.yaml | LiveKit 运行配置；keys.devkey 与 LIVEKIT_API_SECRET 一致 |
| server/token-service/config.example.json | 本地运行的配置示例；容器配置通过 Compose 环境变量覆盖 |
| deploy/.quickshare-deploy | 部署脚本记住的模式与项目名 |

真实配置与证书不提交 Git。不要把 LiveKit 签名密钥填进客户端。

用两台不同网络的电脑验证：开始共享 → 观看画面、声音和聊天 → 停止共享 → 房间消失。[IP 自签名客户端设置](IP自签名HTTPS部署.md#client)。

## 5. 更新与日志

更新源码后，在项目根目录再次运行部署脚本，使用原模式和项目名即可。更新前保留配置、证书及可回退版本；重启 LiveKit 会中断共享。

手动查看日志时进入 `deploy/`，将文件名和项目名换成实际值：

```bash
cd deploy
sudo docker compose --env-file .env -p quickshare -f docker-compose.yml logs --tail=50
```

仅更新 Token 服务、启用新的聊天权限：

```bash
sudo docker compose --env-file .env -p quickshare -f docker-compose.yml up -d --build --no-deps token
```

观众随后退出并重新进入房间。Nginx 证书续期后需重新加载 Nginx；Caddy 自动续期。

<a id="troubleshooting"></a>
## 常见问题

| 现象 | 检查 |
| --- | --- |
| 启动失败 | 日志、端口占用、Docker / Compose、已有配置 |
| 房间列表 401 | 客户端令牌与 AUTH_TOKEN 是否一致 |
| 健康接口正常，房间接口失败 | 两处 LiveKit 密钥是否一致，内部 7880 是否可达 |
| 能进房但没有画面 | 媒体端口、安全组、服务器公网 IP |
| 观众消息不可见 | 更新 Token 服务，观众重新进房 |
| HTTPS 错误 | DNS、证书域名与有效期、入口端口 |

容器无法访问宿主机 7880 时，检查 Docker 子网及现有防火墙，只允许可信子网访问该内部端口。已有 Nginx 方案面向宿主机 Nginx；容器 Nginx 需要另行配置网络。
